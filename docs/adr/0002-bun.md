# ADR-0002: Bun as Runtime and Package Manager

**Status:** Accepted  
**Date:** 2026-06-05

---

## Context

JavaScript projects need:
- A package manager that installs dependencies fast and safely.
- A runtime for the backend that is performant and actively maintained.
- A consistent toolchain across frontend and backend so there is no npm / yarn / node split.

The main candidates were npm, yarn, pnpm, and bun.

---

## Decision

**Use Bun for everything.** Never use npm, yarn, or pnpm. Never invoke `node` directly for running backend code; always use `bun`.

This means:
- `bun install` — never `npm install` or `yarn`
- `bun run <script>` — never `npm run`
- `bun test` — for unit and integration tests
- `bunx` — never `npx`
- Backend entry point runs under `bun src/index.ts` — not via `ts-node`, `tsx`, or compiled `node dist/index.js`

---

## Why Bun

### Performance
Bun installs packages significantly faster than npm and yarn due to its binary lockfile format and aggressive caching. Cold installs on CI are noticeably faster.

### Native TypeScript
Bun runs TypeScript natively. No `ts-node`, no `tsx`, no separate compile step for the backend in development. The `tsconfig.json` is still respected for type-checking; Bun simply does not need a transpiler wrapper.

### Single toolchain
One lockfile (`bun.lock`), one runtime, one test runner. This eliminates the common split where the frontend uses one package manager and the backend uses another.

### `minimumReleaseAge` — Supply Chain Protection

Bun supports a `minimumReleaseAge` setting in `bunfig.toml`. When set, Bun refuses to install a package version that was published less than N seconds ago. This is a lightweight but effective defense against supply-chain attacks that exploit the window between a package being compromised and defenders reacting.

```toml
[install]
optional = true
# 3 days (259200 seconds) — new versions must age before they can be installed
minimumReleaseAge = 259200
minimumReleaseAgeExcludes = [
  # internal/workspace packages are exempt — they are not published to the registry
  "@your-org/shared",
]
```

No other mainstream package manager offers this feature natively.

---

## Consequences

- Every project ships with a `bunfig.toml` configuring `minimumReleaseAge = 259200`.
- CI pipelines use `bun install --frozen-lockfile` to ensure reproducible installs.
- Internal workspace packages are excluded from the age gate because they are not published to a public registry.
- Engineers running `npm install` or `yarn add` by mistake will produce a different lockfile; the discrepancy is caught in review.
- **Rule:** any script, CI step, or documentation that invokes npm/yarn for a project using this stack must be corrected.
